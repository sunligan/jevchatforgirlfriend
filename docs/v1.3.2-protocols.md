## 最简单：只配置一套接口

1. 打开设置，在“回复接口”选择 **OpenAI 兼容** 或 **Anthropic**。
2. 填写 Base URL、API Key、服务商账号实际可用的模型 ID。先选协议再填写；协议切换会设置对应官方地址并清空模型 ID，若使用中转服务请改为自己的地址。
3. 打开上方的 **“判断和排序复用下方回复接口”**。
4. 点“测试当前回复配置”与“测试当前判断配置”。两个按钮都读取当前表单，不用先保存。
5. 两项成功后点“保存全部设置”，回到测试聊天进行分析。

关闭复用时：判断接口单独选择 Jev、OpenAI 兼容或 Anthropic，单独填写地址/密钥/模型；回复接口可使用不同协议、不同模型。
已有 Jev 用户升级后保持原配置，不会被静默迁移到其他服务。要摆脱 Jev，需手动选择普通模型或打开复用。

## 地址示例

| 协议 | 官方 Base URL | 实际请求 |
|---|---|---|
| OpenAI 兼容 | `https://api.openai.com/v1` | `/v1/chat/completions` |
| Anthropic | `https://api.anthropic.com` | `/v1/messages` |

- 两者均支持填写 HTTPS 域名根地址、带 `/v1` 的地址或完整对应接口路径；自定义前缀会保留。
- 使用中转或兼容服务时，填它提供的 HTTPS 地址，不要把文档网页地址填进来。
- OpenAI 模式实现的是 **Chat Completions**，不是 `/v1/responses`；没有实现 Azure 特有部署 URL 和鉴权。
- Anthropic 模式发送 `x-api-key`、`anthropic-version: 2023-06-01`，system 在顶层，必填 max_tokens。
- 模型 ID 请使用自己的服务商账号中可用的 ID；不预填可能失效的 Claude/GPT 别名。
- 没有自动读取订阅账号或 Codex 的登录凭证。需要对应服务商的 API 密钥。
- 空回复/视觉密钥仅可复用同一源站（协议+域名+端口）的密钥，不会跨服务商自动外发另一家的密钥。

## 通用模型输出行为

- 判断：可能意图、风险估计、建议动作、自评把握（低/中/高）、依据、缺失事实。
- 排序：只返回候选顺序，不编造百分比；原始候选文本不会被排序模型改写。
- 对缺字段、非法枚举、截断输出、拒绝、工具调用或非 JSON 判断直接显示错误，不把失败伪装成正常结果。
- 为兼容普通网关，不强制 JSON Schema / response_format，也不发送 temperature；使用提示词约束并严格校验返回。
- OpenAI 首先使用 max_completion_tokens；仅当 HTTP 400 明确表示该参数不支持时，回退一次 max_tokens，不切换服务商或模型。
- 聊天、联系人背景和选中的历史仍会发送到你配置的模型服务。
